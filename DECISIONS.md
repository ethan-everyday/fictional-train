# Decisions

One line per architectural choice. Append, don't rewrite history.

- 2026-06-09 — Next.js 14 App Router + TypeScript + Tailwind; existing stack, deploys to Vercel with zero config.
- 2026-06-09 — Playroom Kit for multiplayer; all playroomkit imports confined to `lib/game/connection.ts` so the Colyseus fallback is a one-file swap.
- 2026-06-09 — Host runs as a Playroom *stream screen* (`streamMode: true`): it owns the room and shows the code/QR but is never in the players list, matching the host-authoritative design.
- 2026-06-09 — `skipLobby: true` everywhere; we render our own lobby UI instead of Playroom's.
- 2026-06-09 — Player identity = Playroom player id; chosen display name stored as player state `name`, never as shared state.
- 2026-06-09 — PING (M1) implemented as player state `{count, at}` rather than RPC; player state survives observers (host) joining late, RPC doesn't.
- 2026-06-09 — `/host` and `/play` pages load their screens via `next/dynamic` with `ssr: false`; playroomkit touches browser globals at import time.
- 2026-06-09 — `qrcode.react` for the join QR; renders SVG locally, no network call.
- 2026-06-09 — No Zustand/Redux, no DB, no auth, no Electron in the prototype (per spec §2).
- 2026-06-09 — Ink compiled at build time by `scripts/compile-stories.mjs` using inkjs's bundled compiler (`inkjs/full`); authoring needs only a text editor, Inky optional.
- 2026-06-09 — All inkjs imports confined to `lib/ink/storylet.ts`, mirroring the Playroom rule.
- 2026-06-09 — Stat-gated choices use a tag INSIDE the choice brackets: `* [Force the door # needs: body 3]` (a tag after the bracket binds to the post-choice content, not the choice). The game shows-but-disables; ink itself doesn't gate.
- 2026-06-09 — Storylets set an `outcome` string var; the host resolve screen renders "<name> <outcome>". Flags are `flag_*` booleans diffed out after each run.
- 2026-06-09 — Picks and storylet results are PLAYER state tagged with the night number; the host derives the room view. One writer per key — no concurrent writes to a shared map.
- 2026-06-09 — Mid-storylet ink saves go to the phone's localStorage (key per room+night), not synced state: survives a phone refresh, costs nothing to sync. Stats/flags survive disconnects via Playroom's reconnectGracePeriod (3 min).
- 2026-06-09 — Host refresh recovery: the host stores its room code in localStorage (2 h window) and rejoins the same room, where Playroom still holds all shared state.
- 2026-06-09 — The finale knot runs on the party's AVERAGE stats so ending thresholds don't scale with player count.
- 2026-06-09 — Phase transitions live in `lib/game/state.ts` and are only ever called by the host screen; phones render shared state and never transition.
- 2026-06-10 — `skipLobby` leaves Playroom profiles without a colour; `playerColor` falls back to a palette colour hashed from the player id (stable per player) instead of crashing.
- 2026-06-10 — Host can kick players from the lobby (`player.kick()` via `kickPlayer` in connection.ts); kicked browsers recover through the host error screen's "clear saved data" button.
- 2026-06-10 — `insertCoin`'s once-only guard resets on failure; a cached rejected promise was bricking every retry (wrong room code, kicked session) until a full reload.
- 2026-06-10 — The host's one-shot transition guard clears when phase returns to lobby; otherwise a second game in the same room never fires its night transitions.
- 2026-06-10 — Phones wipe `7n:save:*` keys whenever they see the lobby phase, so a replayed room can't resume a stale mid-storylet save from the previous game.
- 2026-06-10 — Both screens render inside an ErrorBoundary: a runtime error shows a reload button (reconnection makes reload safe) instead of a dead page mid-party.
- 2026-06-10 — Host gets a force-resolve escape hatch on the storylets screen so one dead phone can't softlock the night; players without a result are simply skipped on the resolve screen.
- 2026-06-10 — Storylets gain flag-gated bonus choices (`* {flag_x} [...]`): flags earned on earlier nights unlock extra options later in the week, making the seven nights one connected story.
- 2026-06-10 — Compiled ink is contract-validated at build time (`scripts/validate-stories.mjs`): every storylet choice path must reach END with `outcome` set, finale knots must be choice-free, gate tags must parse, gates can't exceed STAT_CAP. Walked under night-1 and night-7 scenarios so night-gated content is covered.
- 2026-06-10 — Week history is a player-state array appended by the owning phone (one writer per key holds); `visits` fed into ink is derived from it, not tracked separately. KEY_RESULT stays as the per-night "done" signal.
- 2026-06-10 — Ink context vars (`night`, `visits`, `event`) are written only if the story declares them, mirroring the flag guard — old ink never breaks. Each night is a fresh Story; sequences/cycles don't persist across nights by design.
- 2026-06-10 — Stats clamp to 0..STAT_CAP (5) at the single point they leave ink (readStats), so balance lives in content, not scattered guards. Gate escalation is an authoring convention (3 early, 4 behind {night >= 4}, 5 behind {night >= 6}).
- 2026-06-10 — Drama events: definitions (trigger fns) live in constants.ts, the host rolls them at night-intro off the party's average stats, and shared state stores only {id, night} — phones and a refreshed host look the definition back up.
- 2026-06-10 — Audio is host-only, HTML5 Audio confined to lib/audio/sound.ts, unlocked by the BEGIN THE WEEK click (autoplay policy), silence-tolerant when files are missing. Phones never play sound.
- 2026-06-10 — ARCHITECTURE PIVOT for Steam: Playroom cloud replaced by a self-hosted server (server.js — rooms, state sync, kick, reset, reconnect, disk persistence, static serving). No internet dependency; phones connect over LAN. connection.ts kept its exported API so components barely changed (the one-file-swap rule paid off).
- 2026-06-10 — Host-authoritative on the wire: only host sockets may write shared state; phones write only their own player state. Player identity is a per-tab sessionStorage UUID — two tabs are two players, refresh keeps the slot, and the old same-browser-phantom/kick-lockout class of bugs is structurally gone.
- 2026-06-10 — Reconnect model: clients auto-reconnect with backoff and re-hello; the server holds player slots with an 8s disconnect debounce; the host resolves a night when all *attached* assigned players have reported, so one dead phone can't softlock the party (force-resolve stays as the manual override).
- 2026-06-10 — `next build` is a static export (`output: "export"`) served by server.js (with Range support for audio); one process, one port in production. Dev keeps next dev (3100) + WS server (3199), selected by NODE_ENV in the client.
- 2026-06-10 — Desktop shell is Electron embedding server.js (electron/main.js), packaged by electron-builder (NSIS + portable). Room state lives in the app's userData dir. The browser-served flow (start-game.bat) and the desktop app are the same product.
- 2026-06-13 — Two-beat opening + cinematic scenes (components/Scenes.tsx, SVG, offline): the SETTING prologue (1348 doom + the Herald's vision) is big white text over a boat-at-sea scene (dark swell, bobbing ship, the Herald's pulsing red eyes) on the LOBBY, shown while players build characters; once all have chosen, BEGIN plays the TOWN prologue (arrival at St Sebastian, same sea scene) before week 1. The weekly RESOLVE is a CAMPFIRE scene (flickering fire, warm glow) where the party recounts the week. The EPILOGUE shows every player's personal ending to the whole room (playerEnding per player), not just on their own phone.
- 2026-06-13 — THEME OVERHAUL (Ethan's new direction): St Sebastian, 1348 — fugitives land at a fortress town with seven WEEKS before war/plague/famine + a warband arrive; a red-eyed patron names them its Herald (save the town or flee). Setting renamed Hollowbrook→St Sebastian; player-facing "Night"→"Week" (internal names like NIGHT_COUNT/night-intro kept). New host PROLOGUE phase shows the 1348 vision (state.ts startGame→prologue→beginAfterPrologue). NIGHT_INTROS rewritten as the 7 week escalation; roles/backgrounds re-themed as fugitives (ids/stats/startFlags kept). All 70+ events re-authored to the apocalypse via workflow.
- 2026-06-13 — Events gained optional minWeek/maxWeek so content escalates with the timeline (warband events minWeek 6, etc.); eligibleEvents/pickEvent take an optional week; EventPlayer passes the week; contract + editor validate the range.
- 2026-06-13 — Endings are now 7 town-fates (finale.ts townEnding) scored from the party's SPINE flags across three axes — Defence / Plague / Food — plus a darkness path and the Herald's secret; per-player closing lines (playerEnding) from each player's own choices (fled, served the dark, found the secret).
- 2026-06-13 — Engine unit tests are content-AGNOSTIC: they probe the rules against whatever events exist (find an event with a prereq, assert it's hidden without the flag) rather than naming ids, so re-theming the story never breaks them.
- 2026-06-13 — Content moved from TS modules to JSON (lib/game/content/data/*.json), imported directly by the game (resolveJsonModule). This makes content a clean round-trip data format for the visual editor and keeps a single source of truth (game and editor read the same files).
- 2026-06-13 — Visual STORY EDITOR (dev-only, never shipped): `npm run editor` → scripts/editor-server.js (plain Node, reads/writes the content JSON, validates against the contract before writing) serving scripts/editor.html (self-contained, no CDN — offline). Map view shows the full prerequisite graph (set→require gold edges, forbids red-dashed); Edit view forms with requires/forbids flag pickers and a per-event connections panel. Server rejects any save that fails the contract, so the editor can't break the build.
- 2026-06-11 — GAME MODEL REDESIGN (replaces ink entirely). Loop is now: build a character (1 of 6 roles × 1 of 6 backgrounds → hidden base stats) → each night pick a location → pick 1 of 2–4 activities → a random ELIGIBLE event fires. Ink (inkjs, lib/ink, stories/, the compile+validate scripts) removed; content is TypeScript data in lib/game/content/<location>.ts, the engine is lib/game/events.ts.
- 2026-06-11 — Stats are NEVER shown as requirements. They drive hidden `check: {stat, dc}` branches inside events (pass/fail). Players see their stats (a sheet), never a gate label. This was the explicit design ask.
- 2026-06-11 — Events chain via flags: an event's `flags` satisfy another's `requires`/`forbids`, across locations and nights (tavern met_steward → castle audience_with_lord is the reference chain). Once-only by default; `repeatable` opts back in. Selection is weighted-random, seeded by (playerId, night, activity) so a phone refresh re-rolls the SAME event. Seen-set derived from history eventIds.
- 2026-06-11 — Content is validated in vitest (tests/content.test.ts), not a build script: unique ids, exactly one resolution shape, non-empty outcome/text per branch, real stats/locations/activities, dc ≤ STAT_CAP, and no orphan prerequisites (every required flag is producible). TS-native, runs in npm test + CI.
- 2026-06-11 — Character creation happens on phones in the lobby; the host's BEGIN is gated until every connected player has chosen. "Play another week" keeps name + character (resetRoom preserves both) and re-rolls stats from the character, so it replays with the same people.
- 2026-06-11 — STAT_CAP raised 5 → 10 (base stats run ~1–6 from role+background; a week of gains needs headroom). Finale endings moved from an ink knot to lib/game/finale.ts (prosperity / steadfast / quiet, off the party average).
- 2026-06-11 — The QR join URL is built from the LAN IP the SERVER reports (os.networkInterfaces, home-router ranges preferred), never from the host page's own origin. Opening the host via localhost — which the desktop app always does — can no longer produce an unreachable QR.
- 2026-06-10 — Verification is e2e-first: Playwright drives a host + two phone contexts through ENTIRE seven-night games against the built product, plus protocol-level tests with real sockets. CI runs the lot.
- 2026-06-10 — Setting pivot per Ethan's design board: grounded medieval (no fantasy). Six stats (intelligence/strength/agility/craft/will/wealth — wealth starts at 1 and is spendable, `~ wealth = wealth - 1`), seven locations (church/tavern/market/farms/castle/slums/docks) each with named NPCs (priest, innkeep + gamblers, butcher + armourer, Shire Reeve + farmers, lord, peasants, foreign traders + dockworkers). Week arc: seven nights before the Michaelmas Fair, when the lord reckons accounts. Gambling uses ink `{shuffle:}` for win/lose — both branches must set outcome (validator only walks one).
- 2026-07-02 — WHITE-SCREEN ROOT CAUSE + FIX: os.networkInterfaces() also returns addresses lingering on DISCONNECTED adapters (Windows keeps a deprecated DHCP address on an unplugged NIC), and lanIp() was advertising one in the QR/join URL — every phone black-holed into a white screen. lanIp() now asks the routing table for the source address the OS would actually use (UDP connect to a TEST-NET address — resolves the route, sends nothing), refreshed every 5 s so a mid-evening Ethernet↔Wi-Fi flip updates the QR; interface enumeration is only the fallback. The .bat files' IP display got the matching filter (AddressState Preferred + adapter Up).
- 2026-07-02 — NEW GAME purges all old rooms: the title screen's New Game sends `create {fresh:true}` (first create only — reconnects rejoin); the server closes every other room and its sockets, so a phone holding a dead session reconnects, gets NO_ROOM, and lands on the join form ("that game has ended") instead of silently auto-rejoining — or white-screening on — a stale game. Covered by protocol tests + an e2e. Purged codes are tombstoned (2 h): a lingering host tab auto-reconnecting with a dead code gets ROOM_CLOSED and bounces to the title screen instead of resurrecting a zombie room (start-game.bat opens a fresh /host tab per run, so stale tabs accumulate and were recreating purged rooms).
- 2026-07-02 — Never-render-nothing hardening (stale rooms from other builds were reproducibly blanking phones): renderPhase() on both screens gained a default case (phone: holding screen; host: lobby) because an out-of-vocabulary shared.phase previously returned undefined — a silent white screen with zero errors; locationDef() degrades to a stub instead of throwing; DeltaChips ignores non-number deltas. server.js also now serves HTML with Cache-Control no-cache (hashed /_next/static immutable) and logs page requests + room joins with peer IPs, so "is the phone reaching us?" is answerable from the game window.
- 2026-07-02 — Deep-dive verdict on "phones show a blank screen": the game/server code was conclusively eliminated (full host+player protocol loop passes over the exact LAN URL phones use; 41/41 tests). Root cause on Ethan's PC: AVG Firewall (which REPLACES Windows Firewall — Windows reports its own firewall "off", a red herring) silently drops inbound LAN connections because the Wi-Fi network re-registered as a new Public/untrusted profile ("EE-36WPZH 2"). Fix = mark the network Private in Windows (AVG mirrors it) / allow node.exe in AVG. README troubleshooting rewritten accordingly. Also fixed from the audit: server.log write stream got an error handler (async stream error would have crashed the server mid-party), and tests now use an isolated stateDir (npm test was truncating the LIVE server's log and clobbering its rooms.json).
- 2026-06-25 — Lobby is now purely JOIN + CHARACTER SELECT (room code, QR, and the party roster with each player's chosen calling, then BEGIN). The Herald's 1348 vision moved OFF the lobby into the opening cinematic: the prologue phase is now TWO beats (the vision, then arrival at St Sebastian), which also matches what phones already tell players during prologue ("watch the big screen — the Herald's charge is read aloud"). Also renamed the character-create confirm button Hollowbrook→St Sebastian (stale pre-overhaul name).
- 2026-07-03 — FOUR-THREAT-TRACK doom model (lib/game/threats.ts, pure like events.ts): the town carries four scores — plague / starvation / war / devils — that decide its fate, replacing the SPINE-flag axes of the 2026-06-13 townEnding. Every threat rises when a week ARRIVES on an exponential schedule (THREAT_TICKS = [0,1,1,2,2,3,4], applied at setupWeek to the arriving week; cumulative 13 vs THREAT_CAP 10, so each track needs net −3 of relief across the game to stay under the cap). Event outcomes carry `threats` deltas (negative = relief, positive = recklessness); the host aggregates every player's night deltas at endNight (applyThreatDeltas) BEFORE the finale or the next week's tick. Supersedes the three-axis Defence/Plague/Food scoring.
- 2026-07-03 — Ending tier = COUNT of maxed threats, per Ethan's 0–4 ladder (townEnding, finale.ts): 0 dooms at the cap = full success, 1 = minor success, 2 = minor failure, 3 = major failure, 4 = utter ruin; one vignette per maxed track, tier opener + last line around them. Player flags still colour the edges only — the Herald's secret turns a clean sweep into the BEACON end, a soul given to the dark darkens the devils' vignette; playerEnding (per-player closing line) unchanged.
- 2026-07-03 — EventChoice gains two shapes beyond flat `effect` (contract-enforced exactly-one, like GameEvent): a HIDDEN check inside a single choice (`check` + `pass`/`fail` — a stat decides that option's branch, still invisibly) and a WEIGHTED random pool (`random: [{weight?, effect}, …]`, 2+ outcomes) the dice settle. choiceRoll(playerId, night, activityId, chosenIndex) is mulberry32-seeded exactly like event selection, so a phone refresh re-rolls the SAME result. Lets one activity (e.g. tavern Gamble, docks Slack off) branch on luck without a whole new event.
- 2026-07-03 — Activities re-cut to Ethan's design board: Tavern = Drink / Gamble / Work behind the bar; Docks trimmed to Talk to the traders + Haul cargo (the three foreign ships — Spanish food+friendship→a way aboard the Moorish ship, Frisian weapons+the market heist+a devil rumour, closely-guarded Moorish ship reached by will or agility — hang off Talk to the traders; Haul carries the strength-paid / slack-off luck split); Market = Talk / Watch the performers / Fight crime; Church = Prayer / Repair work / Talk to the flock; Castle = Tilt in the yard / Join the banquet / Gossip with the staff; Slums = Give alms / Fight crime / Gamble in the streets. Farms keeps its activities with threat deltas wired in.
- 2026-07-03 — Threats are the one thing SHOWN on the host (ThreatMeters.tsx — four labelled meters climbing toward the cap) while stats stay hidden: triage IS the strategy. The party reads which doom is running away and spends its weeks there; nobody ever sees a stat, a DC, or a threat number framed as a requirement.
- 2026-07-03 — STORY EDITOR resurrected + hardened: a missing paren shipped in the 2026-06-13 theme overhaul had left editor.html unparseable (blank page) ever since — nothing in CI parses the editor, so tests/editor.test.ts now keeps its exported validate() in LOCKSTEP with the build contract (the live story must validate clean; every defect class the contract rejects must be rejected here too) and the contract gained the missing weight rule (positive integers — a saved negative weight would corrupt the engine's weighted pick).
- 2026-07-03 — Editor saves are always undoable: every save (and every restore) first snapshots the files it overwrites into .seven-nights/editor-backups (last 20 kept), with a header Restore dropdown; EDITOR_DATA_DIR / EDITOR_BACKUP_DIR env overrides point the whole server at a sandbox so tests and browser-driving never touch the real story. - 2026-07-03 — EDITOR OVERHAUL, map-first: chains are DERIVED, never authored — connected components of the requires/forbids flag graph, with "ubiquitous" colour flags (3+ setters across 2+ locations) excluded from grouping so the story splits into its real 17 storylines instead of one blob.
